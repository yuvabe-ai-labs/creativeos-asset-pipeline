## YUV-167 — Tray shows generation as failed even when image gen succeeded

**Fixed:** 2026-07-10
**Area:** Canvas → Generation Tray

### Problem

After triggering an image generation, the Generation Tray briefly showed the job as `"failed"` while it was still running, then self-corrected to `"ready"` once the model responded. No bad DB write — all `generations` rows end up `succeeded`. Purely a client-side derivation bug.

### Root cause

`deriveTrayItems` in `src/lib/generation-tray.ts` derives a `"failed"` status for any image job whose `status` is still `"running"` after `STALE_RUNNING_MS` milliseconds — a safety net for disconnected clients. The value had been set to `2_000` ms (a debug artefact), which is shorter than any real image generation (DB data shows 20–32 s typical). So every image gen triggered the stale path, flashing `"failed"` for the entire time the model was processing.

The stale check only applies to image jobs — video is excluded because its pipeline owns its own reconciliation.

### Fix

Raised `STALE_RUNNING_MS` from `2_000` to `300_000` (5 minutes) in `src/lib/generation-tray.ts:36`. This is longer than any realistic image gen timeout, so the fallback only fires for genuinely abandoned jobs (client disconnected mid-request).

| File | Change |
|---|---|
| `src/lib/generation-tray.ts` | `STALE_RUNNING_MS = 2_000` → `300_000` |

### Non-goals

- No DB schema change. No change to the Realtime subscription or tray hydration logic.
- Video gen stale handling not touched — it uses a different pipeline path.
