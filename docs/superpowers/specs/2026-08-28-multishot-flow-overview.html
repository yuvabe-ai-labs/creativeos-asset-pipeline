Design overview · 28 Aug 2026

Shot-Level Multishot

Some shots want several cuts in one generation; most want a single continuous take. So multishot becomes a property of one shot — not of a script, and not of a model setting. The parse gains one number, the shot gains one toggle, and the two nodes downstream read it.

Gemini Omni 1.1 Flash One toggle per shot 10s cap References are File nodes

01

The flow

Script parsing is unchanged apart from one added number. Grouping happens when the script fans out into shots — on the canvas, where it is visible and can be corrected by hand.

Script Raw script text, pasted or uploaded
→
Parse Unchanged, except each shot now returns its length as a number
→
Fan out Packs consecutive shots up to 10s. Mixed by construction.
→
Motion prompt Reads the toggle → a cut ladder, or a single-take prompt
→
Video gen Reads the toggle → model list and duration follow the shot

A multishot shot goes straight to the motion prompt — it does not need to go through the image-gen flow. There is no start frame to generate: the video is made from the shot's own description plus any reference images attached to it. The image-gen path stays exactly as it is for shots that do want a still to animate. It becomes one option rather than a required stage — which is the practical reason multishot is worth having, since a cut sequence is described rather than animated from a frame.

02

Fan-out produces a mix

Five parsed shots totalling 22 seconds. Fan-out walks them in order and closes a node before the next shot would push it past 10s — so the canvas comes out mixed, which is the point.

Shot 1–2 MULTISHOT · ON 9s
[0–4s]Hands lift the jar from a linen surface, morning light
[4–9s]Macro — the balm catches light as the lid turns
Shot 3 MULTISHOT · OFF 4s
singlePriya smooths it along her forearm, unhurried
Shot 4–5 MULTISHOT · ON 9s
[0–5s]She sets the jar down beside a cup of tea
[5–9s]Hero hold — label readable, CTA-safe negative space

22 seconds in, 22 seconds out. Shot 3 stands alone because folding it into the first node would make 13s, over the cap. Grouping is deliberately simple — consecutive shots, filled until the cap. It is not trying to find clever seams; you see the result as nodes and adjust it with the toggle, in the place the work already is.

What the toggle does
The node holdsToggleResult
Several shots, on→ offSplits back into one node per shot, order preserved
One shot, off→ onOne generation; the model may cut inside this single shot
One shot, on→ offOne generation, one continuous take

Turning multishot off on a grouped node creates nodes — it is a real change to the canvas, so it confirms first and can be undone. There is no merge action for now; to regroup, re-run the fan-out. Merging raises questions worth answering properly later (which side's edits win, what happens to anything already wired downstream) rather than guessing at now.

Why the parse has to return a number

Today a shot's length comes back as free text copied out of the script — "22-26 seconds", "3 sec", "0-3s". Grouping to a 10-second cap needs arithmetic, and working it out from that prose would quietly fail on any format we didn't anticipate. The model already reads the duration; it now also returns it as a plain integer. Anything missing falls back to 4s and is shown as an assumption rather than a fact.

03

References are just File nodes

No separate character library, no script-level setup, no new screen. A reference is a File node, attached with the + that already sits on the motion prompt and video generation views. The File node's title is the reference's name, and the prompt mentions it by that name.

Inputs are given per shot rather than per script, so one character or prop can be attached to exactly the shots that use it. Everything needed for this already exists — the uploads, the thumbnails, the naming and the connection control — which is why it adds no new surface to learn.

04

What the downstream nodes do with it

Both nodes look upstream at the shot and adapt. Nothing has to be set twice.

Motion prompt
Multishot Writes a timed cut ladder across the shots in the node, adding up to its total length.
Single Today's motion prompt, plus an explicit instruction to hold one unbroken take.
Video generation
Multishot Model list narrows to Gemini Omni, with the reason shown.
Single Every model available, Omni included.
Duration Defaults to the shot's own length, editable, labelled with where it came from.
Why the model list narrows rather than warns

Omni is currently the only model that cuts between shots natively. Sending a timed cut ladder to any other model returns a single continuous take with the timings silently ignored — which is indistinguishable from a bug, and only discovered after paying for the generation. A model that cannot honour the prompt should not be selectable for it.

05

Controls

All controls stay on the video generation node, exactly where they are for the existing models. What differs is only how each one reaches the model — three are settings on the request, three are written into the prompt, because Omni has no field for them.

There is no separate "continuous take" control — the shot's multishot toggle already is that decision, and two controls for one thing is the pair that drifts apart. Kling's own multi-shot option is hidden, so multishot means one thing in one place. On-screen text is worth asking for because Omni renders type legibly, though a brand lock-up is still composited in post rather than generated.

06

What it costs to run

Grouping shots already reduces the number of generations — the 22-second reel above is three requests rather than five. Resolution then decides what each one costs, and the draft tier is cheap enough to iterate on freely before committing to a final render.

ResolutionPer secondThe 22s reel, 3 nodes
360p$0.03$0.66Draft tier — also around 60% faster
720p$0.10$2.20The default, and the only natively rendered tier
1080p$0.15$3.30Upscaled from 720p
4k$0.30$6.60Upscaled from 720p

Worth knowing when setting expectations: 1080p and 4k are upscales of a 720p generation, not rendered at that resolution — so they cost 1.5× and 3× without adding real detail. Audio is always generated and already included in the rate. Credit estimates appear on the node before generating, as they do for the existing models.

07

Build order

Each step leaves the product working and useful on its own.

1
Add Gemini Omni as a model

Provider, controls and pricing. Usable immediately with hand-written prompts, before any of the shot work lands.

2
Parse and fan-out

Shot lengths as numbers, grouping to the 10-second cap, the multishot toggle and the split.

3
Wire the downstream nodes

The cut ladder in the motion prompt; the narrowed model list and derived duration in video generation.

4
Tidy up Kling

Hide its multi-shot option so multishot means one thing in one place.
