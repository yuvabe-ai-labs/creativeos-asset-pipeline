Omni Multi-Shot Pipeline

Integrating Gemini Omni 1.1 Flash into the asset pipeline — a model with no shot-count field, no negative-prompt field, and no audio switch, that cuts between shots by default. The prompt is the storyboard. That single property is what reshapes script parsing, the reference model, and three UI surfaces.

02 · D188

One parse, two planners

The same parsed script, planned two ways. Per-shot is the identity planner — one block per shot, no LLM call. Multi-shot packs shots into ≤10s timecode blocks, because Omni cuts natively and a shot-per-generation wastes the model entirely.

Shot 5 gets its own short block rather than being squeezed into Block 2: 4+5+4 is 13s, over the hard 10s ceiling. A block is closed by the ceiling, and the leftover opens the next one.

Toggling costs nothing. Both planners run over the already-parsed shots[], so switching never re-runs the parse and never discards manual edits — the parse is the operator's working document, not a cache. Fewer generations is not the goal — conserving the script is. Packing is bounded by the 10s ceiling, so a 22s reel is three generations, not two.

D189 — the plan is validated, never trusted

Omni's timecodes are a request, not a configuration. A ladder whose beats don't sum to duration returns a truncated ending at full price. Every returned plan is checked, and a failing plan is rejected in favour of a deterministic seam-packer. The LLM supplies judgement about where the seams are; it is not trusted with arithmetic.

Conservation is the guardrail that matters most. ∑ block durations must equal ∑ shot durations, and each shot's allocated time must equal its parsed duration. The per-block checks alone are not enough: a plan can be internally consistent in every block and still quietly drop four seconds of script, and nothing downstream would ever generate them.

Guardrails Checked on every returned plan
InvariantScopeCatches
∑ blocks = ∑ shotsWhole planSilently dropped footage — the one that bit this spec

A shot longer than 10s cannot fit one generation, so it may span blocks — but only at a beat boundary, and its total allocated time must still equal its duration. That is the single exception to “a shot belongs to one block”.

03 · D190

A cast at the script level

Characters, props and style anchors live on the Script node, are proposed by the parse, and are copied into each forked Shot — the same seed-and-fork the script text already uses. kind is load-bearing, not decoration: Omni assigns a reference's role by the sentence its tag sits in, so a style member renders as “in the style of…” and a character as “the woman…”.

The parse proposes names and kinds only — never images. A re-parse merges by name and preserves every upload; a name that disappears from the script is kept rather than deleted, because the operator may have renamed it deliberately. Nothing destroys an upload.

Two sources, one ordered list The cast is not the only way in

A reference can come from the script cast or from an image node connected straight to the motion-prompt or video-gen node. Both land in the same UpstreamImage[] list and get identical Start / End / Ref chips — the cast is reusable across every shot, a direct connection is a one-off for this shot only.

1 · Cast members In cast order, from the Script node. Script-level, inherited by every forked Shot.
2 · Direct connections In canvas connection order, after the cast. One-off, this node only.

Order is fixed, and that is the point. <IMAGE_REF_N> is positional, so a mixed list without a rule would renumber the whole cast the moment you connected a one-off. Cast first means appending a direct ref only ever adds an index at the end. A direct ref has no cast kind, so it defaults to subject phrasing, with a kind selector on its role row for the cases where it is really a style anchor.

Accepted cost

Editing a cast image at script level after forking will not propagate to already-forked Shots. That's the same trade the script text already makes under D21, so the model stays uniform — but it is a real limitation, and binding cast entries to canvas nodes instead remains available if it bites in practice.

Three index bases, one renderer

This is the subtlest thing in the build and the one that fails silently. The prompt-writing LLM emits mention tokens only. Indices are assigned once, in code, per generation — over just the references actually being sent.

Worse, Omni's own declaration header carries two bases in one line: @ImageN counts the whole upload array from 1, while <IMAGE_REF_N> counts the references sub-array from 0. So the provider always generates the explicit header from assignImageRoles() output — never simple inline tags, even when roles look unambiguous.

Generated header — always, never hand-written
[# Sources <FIRST_FRAME>@Image1] [# References <IMAGE_REF_0>@Image2 <IMAGE_REF_1>@Image3] [0-4s] Priya <IMAGE_REF_0> lifts the jar <IMAGE_REF_1> from linen, a slow push-in at a constant focal length. Low morning sun from camera-left. Sound design: ambience and foley only. No dialogue. No extra sound effects. Avoid: warped label, drifting text, floating objects. Use Image1 as the starting frame. Use the given images as references for video generation. The images should not be used as literal initial frames.
Frames Tags, not parameters

There is no start-frame or end-frame param on Omni. They are <FIRST_FRAME> and <LAST_FRAME> tags declared in the same generated header, and <LAST_FRAME> requires <FIRST_FRAME> — the one structural constraint rule. The model's conversational side is previous_interaction_id editing, a different axis entirely, and out of scope here.

Block-level, not beat <FIRST_FRAME> is the first frame of the whole 9s block — not of each cut inside it.
End frame fights a ladder Asking the model to land an exact final frame after inventing cuts is close to incoherent. On a multi-beat block this warns rather than blocks.
Continuity chains forward Block N's derived end frame becomes block N+1's <FIRST_FRAME>. Real state transfer — it carries grade, light direction and grain that no adjective will.

The chaining machinery already exists: derive-end-frame.ts extracts a generated video's last frame into a new image node. Nothing new is needed for continuity across blocks — only for surfacing it in the storyboard strip.

06 · D187

Params — and the three that aren't

Omni has no negative-prompt field, no audio switch and no shot-count control. Three controls on the panel render as sentences appended to the prompt, and the param file says so loudly.

Every param is in the primary group. The Advanced accordion was deleted from the focus view in 7e1c643, so an advanced control renders nowhere — the trap aspect_ratio already fell into on Kling O1.

The default inverts against Kling — read this twice

Kling's multi_shot defaults to false: you opt into cutting. Omni multi-shots by default, so continuous_take defaults to false to opt out of suppressing it. Same intent, opposite switch. Anyone reading them as the same toggle gets the reverse of what they asked for.

07 · Cost

Why 360p changes the workflow

A 22-second reel fans out to six 8-second generations. At the draft tier that's a $1.44 exploration; at 720p it's $4.80 every time you re-roll. That difference is what makes iterating affordable, and it's the main reason this targets the stable 1.1 rather than the 720p-only preview.

ResolutionPer secondOne 8s clipSix-shot fan-outNote
360p$0.03$0.24$1.44Draft tier — ~60% faster
720p$0.10$0.80$4.80Native, and the default
1080p$0.15$1.20$7.20Upscaled, not native
4k$0.30$2.40$14.40Upscaled, not native

Audio is always generated and always included in the rate, so Omni slots into the existing resolution-keyed pricing shape unchanged — VEO_RESOLUTION_PRICING is renamed RESOLUTION_ONLY_PRICING to stop being a lie about who it serves.

08 · Scope

What's deliberately left out

Every open regression on the Google AI Developers Forum is on a video-input path. This pipeline sends images only, so none of them are on our path — and that's also exactly why these three stay out.

Extend chain 3×10s → 40s via task:"extend". Real feature, own spec — needs interaction-id persistence and a chain UI. Note store:false must flip to true when it lands.
Stateful edit turns Currently failing during polling with a malformed blobstore:// URI. Would need a re-generate fallback for every edit turn.
Video references Precisely the input path the open 400 regression kills — and there is no video-input source in this pipeline today.
